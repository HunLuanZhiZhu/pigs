实验说明： -pig3 是诊断专用后缀：使用仅规划的 Pre 并禁止简单路径提前完成，随后进入 Executor / Post；最终输出沿用模式 B。普通 -pig 与 -pigs 行为不变。

pigs-protocol

当前实现不是“纯 serde 结构体字典”，而是一组基于 serde_json::Value 的协议工具：路径判定、请求体手术、JSON/SSE 输出解析、增量流解析和客户端响应合成。

调试提示：protocol 负责解析/合成，但不自行写抓包。proxy 的 HTTP 诊断 max 模式会把解析前的原始 JSON/SSE 请求与响应分别落盘，可用于比对协议层是否丢字段或改写形状。

模块职责

模块当前职责

协议路径

protocol_from_path 会先去掉开头的 /，然后识别精确路径或以下后缀：

  • OpenAI Chat：chat/completions
  • Anthropic Messages：v1/messages
  • OpenAI Responses：responses

因此带前缀的路径只要以相应协议路径结尾，也会被识别。Protocol::append_suffix() 仍存在，但当前 proxy 真正转发时使用的是客户端原路径，并没有用它重写路径。

PIGS model 后缀规则

parse_pigs_model 是模式解析入口：<model>-pigs → 模式 A，<model>-pig → 模式 B；两者都剥成同一个真实上游 model。has_pigs 对两种后缀都返回 true，strip_pigs_suffix 只返回剥离后的真实 model。旧后缀 -pigsb 继续兼容，行为与 -pig 相同。

例如 claude-x-pigs 与 claude-x-pig 都发往上游 claude-x。是否进入编排还要由 proxy 同时判断 HTTP 方法和协议路径。

模型后缀与 Pre 内容是两层路由：本 crate 只识别 -pigs / -pig / -pigsb 后缀并读取、改写模型名；DeepSeek v5、Muse v6 和通用 Pre 的选择由 orchestrator 读取真实模型名完成，协议层不匹配模型品牌。

请求体手术

所有请求修改直接作用在 serde_json::Value 上。

  • set_model：覆盖顶层 model。
  • has_client_stream：读取顶层布尔 stream。
  • append_to_last_user_text：在阶段开始时，把 Pre/Executor 提示追加到当前任务 user 文本。
  • append_transcript_items：同一 pig 内恢复工具对话时，只追加已保存的原生 assistant/tool 记录，不新增阶段 user 提示。
  • append_instruction 仍是通用 helper，但当前 orchestrator 的工具恢复主链路不再用它重复注入相位提示。
  • push_assistant_message：按三协议各自格式追加 assistant 产物。
  • push_user_message：追加新的 user 消息；Responses 的字符串 input 必要时会展开为 message 数组。orchestrator 用它追加 Post 核验指令；Post 返回 PIGNEXT 时则先恢复 Executor checkpoint，再用同一 helper 追加由原 Executor 模板生成的新 user 指令。

图片、文档等非文本 part 在“向最后 user 文本追加提示词”时不会被删除。

set_stream 与 strip_tools 仍是公开通用函数，但当前 orchestrator 主链路不调用它们；因此不能从这些 helper 的存在推断当前会改 stream 或删 tools。

上游输出解析

JSON 与 SSE 输出会被统一解析成 ModelOutput。统一内容序列使用 Part 表示文本、reasoning/thinking、工具调用以及协议原生块。

工具调用会同时保存统一字段和协议原生 JSON，以便最终响应尽量恢复客户端所需形状。停止原因与 usage 也从上游输出中提取。ModelOutput::is_truncated() 会把 length、max_tokens、max_output_tokens 识别为生成上限截断，供 orchestrator 区分“被截断”与“真正没有文本/工具调用”。

这不是“任意上游 JSON 原样往返”：只有解析器明确提取/保留的内容会进入统一模型，顶层响应 id、时间戳和其它未建模元数据不会作为原始响应整体保留。

响应合成

synthesize_json 根据统一 ResponseContent 新建三协议响应，而不是序列化回原上游对象：

  • OpenAI Chat：生成新的 chatcmpl-* id、created、choices/message；
  • Anthropic：生成新的 msg_* id、content blocks、stop_reason；
  • Responses：生成新的 resp_* id、output/status/incomplete_details。

model 由调用方传入；proxy 在编排路径传的是客户端原始 PIGS 模型名（-pigs 或 -pig）。usage 缺失时，非流式合成以空对象作为基础值。

因此旧文档中的“解析后可原样序列化回去、字节级等价”不成立。编排响应的设计就是合成新协议响应。

SSE 与实时流

SseTextStream / 实时解析逻辑可以接受任意字节分块，逐步恢复三协议事件。StreamEncoder 则负责把统一事件写回客户端协议。

它支持文本增量、reasoning/thinking、signature、工具调用及收尾事件。proxy 在编排流开始时先调用 start()，相位执行过程中持续 push，最后根据最终 stop_reason / usage 调用 finish()。finish() 会先关闭任何仍打开的协议块；对 Responses，这保证 response.completed.response.output 包含已经提交的最终文本。

synthesize_sse 是把完整 ResponseContent 一次性经过同一编码器生成完整 SSE 文本的辅助路径。

边界

这个 crate 不发 HTTP，也不决定 upstream、鉴权覆盖、重试、continuation 存储或 PIGEND/PIGNEXT/PIGFAIL 的状态机语义；这些属于 proxy/orchestrator。它负责的是“识别和改 JSON、读上游协议输出、写客户端协议输出”。
