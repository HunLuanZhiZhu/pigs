pigs（可执行入口）

电源开关。目标体量：不到一百行，且永不增长。

它干嘛的？（ELI5）

整栋楼的电闸。有人按下开关（运行 pigs.exe），它做四件事然后退场：

  1. 看一眼命令行参数（要改端口/地址吗？要导出配置模板吗？）；
  2. 找 config.toml：没有就生成一份默认的并直接启动（passthrough 不用填 key，开箱即用）；
  3. 把日志打开（固定写 logs/pigs.log）；
  4. 喊一声"前台开业"——调用 pigs_proxy::serve(config)，然后自己一直堵在那一行，直到进程被杀。

计划内容

命令行作用
pigs读 config.toml 启动（无配置则生成默认配置并启动）
pigs --listen 127.0.0.1:4000临时覆盖监听地址（不改文件）
pigs --base-url http://…临时覆盖上游地址
pigs --example把内嵌配置模板导出到 config.example.toml（覆盖旧文件）
pigs -h / --help帮助（附配置模板全文）
[package] pigs  (bin)
├─ 读参数 → 读配置 → 日志 → pigs_proxy::serve()
└─ 结束，共约 60–90 行

红线

任何业务逻辑都不许出现在这个 crate 里：没有路由、没有协议、没有编排、没有重试。 它出现第一处 if model.contains("-pig") 就是架构事故——那行代码的家在 pigs-proxy 或 pigs-protocol。

验收标准：删掉这个 crate，其余三个照常编译、照常跑测试。它只是插头。
