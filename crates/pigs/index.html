pigs（可执行入口）

当前实现：解析命令行、加载/生成配置、初始化日志，然后调用 pigs_proxy::serve(config)。

启动流程

  1. 解析 -h/--help、--example、--listen、--base-url。
  2. 若 config.toml 不存在，直接把内嵌模板写到当前目录，再继续启动。
  3. --listen 临时覆盖监听地址；--base-url 临时把三个协议 upstream 都设成同一地址。
  4. 校验 upstream.openai、upstream.responses、upstream.anthropic 都非空。
  5. 初始化控制台 + 按天滚动文件日志，然后启动 proxy。

命令行

命令当前行为
pigs读取 ./config.toml；缺失时生成默认文件并继续启动。
pigs --listen 127.0.0.1:4000仅本次运行覆盖监听地址。
pigs --base-url http://…仅本次运行把三协议 upstream base 统一覆盖成该地址。
pigs --example把根 config.toml 的内嵌模板写成 config.example.toml，然后退出。
pigs -h / --help打印简短帮助并退出；当前不会附加整份配置模板。

日志

logging.rs 同时输出到控制台和文件。文件使用 tracing-appender 的 daily rolling，目录是 logs/，前缀是 pigs.log；实际文件名会带日期。日志级别由 RUST_LOG 控制，默认 info。

职责边界

这个 crate 当前不实现协议解析、-pigs 路由、编排或重试；这些逻辑分别在 pigs-proxy、pigs-orchestrator 与 pigs-protocol。

配置来源：pigs-proxy::config_template() 最终来自根 config.toml 的 include_str!；因此根配置文件同时是默认模板。
