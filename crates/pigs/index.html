pigs（可执行入口）

当前实现：解析命令行、加载/生成配置、初始化日志，然后调用 pigs_proxy::serve(config)。

启动流程

  1. 解析 -h/--help、--example、--listen、--base-url、--log-detail、--log-dir。
  2. 启动时优先读取 config.local.toml；不存在时读取 config.toml；两者都不存在才把内嵌模板写成 config.toml 后继续启动。config.local.toml 用于本机私有配置并由 Git 忽略。
  3. --listen 临时覆盖监听地址；--base-url 临时把三个协议 upstream 都设成同一地址；--log-detail / --log-dir 覆盖 HTTP 抓包配置。
  4. 校验 upstream.openai、upstream.responses、upstream.anthropic 都非空。
  5. 初始化控制台 + 按天滚动文件日志，然后启动 proxy；流式 Responses 的最终协议收尾由 proxy/协议层保证，终止对象会包含已提交正文。

命令行

命令当前行为
pigs优先读取 ./config.local.toml，否则读取 ./config.toml；两者都缺失时生成默认 config.toml 并继续启动。
pigs --listen 127.0.0.1:4000仅本次运行覆盖监听地址。
pigs --base-url http://…仅本次运行把三协议 upstream base 统一覆盖成该地址。
pigs --log-detail off|basic|max覆盖 HTTP 诊断抓包详细程度。
pigs --log-dir PATH覆盖 HTTP 抓包文件目录。
pigs --example把根 config.toml 的内嵌模板写成 config.example.toml，然后退出。
pigs -h / --help打印简短帮助并退出；当前不会附加整份配置模板。

日志

logging.rs 同时输出 tracing 日志到控制台和文件。文件使用 tracing-appender 的 daily rolling，目录是 logs/，前缀是 pigs.log；实际文件名会带日期。日志级别由 RUST_LOG 控制，默认 info。

另外，proxy 的 HTTP 诊断抓包由 [logging] 配置控制。当前测试阶段默认 detail = "max"，目录默认 logs/http：每个请求/响应各写一个文件，并记录完整 JSON/SSE body；basic 只写元数据，off 关闭。敏感鉴权头会打码，但 body 不做语义脱敏。

职责边界

这个 crate 当前不实现协议解析、-pigs/-pig 路由、编排或重试；这些逻辑分别在 pigs-proxy、pigs-orchestrator 与 pigs-protocol。当前 orchestrator 契约中，-pigs 选择模式 A、-pig 选择模式 B；两者共用状态机。Post 使用 PIGEND/PIGNEXT/PIGFAIL 做纯核验路由：PIGNEXT 回 Executor 修补；Pre 与 Post 使用不同的控制标记有效性规则，并会把明确的 token 上限停止原因视为截断错误；CLI 不覆盖这些语义。

配置来源：pigs-proxy::config_template() 最终来自根 config.toml 的 include_str!；因此根配置文件同时是默认模板。
