pigs-proxy

前台本台：一个端口接住所有请求，按 -pig 分流，剩下的全是"搬运"。

它是干嘛的？（ELI5）

前台坐在窗口，只做三件事：收件、看标签、送件。 收件——任何客户端发来的 HTTP 请求都接住；看标签——model 名字带不带 -pig； 送件——不带标签的原封不动送去上游，带标签的转手给秘书处（orchestrator）。 前台不理解条子的内容、不决定条子的命运、从不重试——理解是字典（protocol）和秘书处（orchestrator）的事。

一次透传的完整流程（无 -pig）

客户端请求 ▼ 1. 收下 body、headers pigs-proxy ▼ 2. 读出 model，查后缀 → 没有 -pig 原样转发：base_url + 原路径 ▼ 3. 上游响应（JSON 或 SSE 流）原样回传 客户端收到

"原样"的意思：方法、路径、查询串、body、端到端头（鉴权等）一个字节不改。proxy 对请求内容是"文盲"，这是刻意设计。

必须带上的修复：content-encoding（血泪教训）

legacy 版的真实事故：透传时把客户端的"我可以收压缩包裹"（accept-encoding: gzip）原样转给了上游， 上游真的回了压缩包裹，但 legacy 在回传时把"此件已压缩"的标签（content-encoding 头）撕掉了。 客户端拿到一团 gzip 字节，以为是明文，JSON.parse 直接炸出 "Failed to parse JSON"。

mini-proxy 已修（标签跟着包裹走）。重建 pigs-proxy 时必须带上这条修复：响应头只跳过 content-length / connection / transfer-encoding 三个逐跳头，content-encoding 必须随 body 转发。 （legacy 出事位置：legacy/crates/pigs-proxy/src/upstream.rs:272）

有 -pig 时：与秘书处的握手

  • proxy 把解析好的请求交给 pigs-orchestrator，拿到"一串子请求 + 合成逻辑"；
  • 子请求通过 loopback（本机回环）再进 proxy 自己的透传通道发往上游——为什么绕一圈？ 因为透传通道里所有"搬运"细节（头处理、流式、错误返回）已经写好了，秘书处直接复用，不另造轮子；
  • 回环请求带一个随机内部令牌，handler 验证后跳过 -pig 分流（否则无限递归），发往上游前删掉令牌（不泄露）；
  • 客户端要流式（stream:true）时边编排边推帧：先把协议起始帧发出去（连接立刻变成流）， 之后每只 pig 的安全文本一到就转成协议 SSE 帧推给客户端，跑完再补终止序列；中途出错发流内错误帧（HTTP 状态此时已定，改不了了）。 客户端没要流式时才等编排跑完一次性给 JSON；
  • 子请求的 body 是编排层拼的（只改 model 名 + 尾部追加指令），proxy 只管照单发出去； 回客户端的 model 是客户端请求的那个名字（带 -pig）。
  • 模型要工具 → 编排暂停，proxy 把调用作为终止帧发给客户端（三协议各自的原生形状）； 客户端执行完带工具结果再发一发，proxy 按 tool_call id 取出现场，交给编排层接着同一只 pig 继续。

配置加载

3 行 toml（listen / base_url / 可选 key）。首次运行没有配置文件 → 生成默认配置并直接启动（passthrough 无需填 key）。 模板用 include_str!("../config.toml") 嵌入二进制（mini-proxy 同款做法），支持 --example 导出。

刻意不做（与 legacy pigs-proxy 的差异清单）

删掉的功能为什么
retry.rs 整套同渠道重试双层重试会把上游抖动放大成请求风暴（10000×N 次）；健壮性归下游 Agent 或 mini-proxy
model_map / models 列表 / 多供应商选择 / 未注册兜底分流只看 -pig 字符串规则，上游只有一个 base_url
thinking_effort 注入归 mini-proxy（或下游 Agent 自己带）
x-opencode-session 补头与 is_opencode归 mini-proxy；编排的会话头由 orchestrator 生成并透传
[provider.aux] 未识别路径透传暂不需要，要时再加

从 legacy 收编什么

server.rs（路由骨架，669→瘦身）、upstream.rs（透传+SSE 预读，带 content-encoding 修复）、 log.rs（双输出日志）、loopback.rs（回环+令牌，改放 orchestrator 还是留这里待定——按依赖方向定）。
