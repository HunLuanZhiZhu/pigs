# PIGS 智能体基准验证顺序建议（2026-10-20）

> **性质：独立研究建议，非已执行计划/实验结果。**
>
> **建议日期：2026 年 10 月 20 日**  
> **适用项目：[PIGS](https://github.com/HunLuanZhiZhu/pigs)**  
> 本文不替换现有 [正式评测方案](./EXPERIMENT_PLAN_CH.md) 和 [运行说明](./README_CH.md)。实施前需确认资源、实际模型版本和评测程序兼容性。

## 1. 研究目的及筛选原则

研究目标不是评价基础模型的纯知识储备，而是检验 PIGS 的 **Pre（规划）→ Exec（执行）→ Post（核验）** 编排，在**相同底层模型、相同外层 Agent / 工具 / 环境**下，能否提升端到端任务成功率，以及改善是否值得额外令牌、时间与费用。

筛选原则：

1. **尽量无需多轮用户/模拟用户交互。** 可以有多轮模型—工具往返（这是研究对象），但应一次性给定任务目标，之后由智能体自主执行。
2. **优先选择 DeepSeek V4.1-Flash-1017 已经披露成绩的基准**，便于建立背景参照；官方成绩不等于在不同 Agent、数据划分或预算下可以直接复现。
3. **优先提供官方评测程序及现成参考 Agent**，减少自定义评测框架、外部搜索服务、特殊硬件和人工评分。
4. 采用完整公开正式划分作为主结果；少量抽样仅用于接口联调及成本校准，不能称为正式全量成绩。

## 2. 建议验证顺序

| 顺序 | 基准 / 公开任务量 | 官方可用执行方案 | 为什么先/后测 | 1017 披露成绩与可比性 |
|---|---|---|---|---|
| **第一** | **Automation-Bench**，公开正式任务 600 题 | Zapier 官方 `auto-bench`：自带工具循环、模拟企业应用及状态评分 | 配置相对简便，不需桌面虚拟机；最直接检验流程规划、跨工具执行、漏步骤与结果核验 | **60.5%**；公开/私有划分及精确配置须再次核实，不能未经确认即视为完全同条件 |
| **第二** | **DeepSWE v1.1**，113 题 | DataCurve **Pier + mini-swe-agent**，隔离开发环境与独立验证容器 | 检验长程代码修改、测试反馈与修复；官方 Agent 路径清晰，但 Docker 环境和评分审计成本较高 | **77.0%**；必须对齐 Agent、模型配置、版本和预算，已知评分争议需逐题记录 |
| **第三** | **NL2Repo-Bench**，104 题 | 官方 **OpenHands** 无界面批量执行模式 + Docker 测试 | 补充“从零搭建完整项目”能力，避免仅依赖修改现有仓库的代码任务；部署和适配成本更高 | **68.2%**；DeepSeek 前版披露使用 **DeepSeek Harness Minimal**，1017 的精确 Agent 配置尚未直接确认；OpenHands 分数不可直接与该值等同 |

**建议总体路径：先 Automation-Bench，再 DeepSWE，最后 NL2Repo-Bench。** 正式公开任务共 **817** 题；若只比较 Base 与 Base + PIGS 两臂，至少需 **1634 次独立任务运行**（不包括内部工具调用、失败重试和多次采样）。

### 第一阶段：Automation-Bench

- 用官方简单任务进行连通性测试，再抽少量正式领域任务检查工具参数、状态变更、失败恢复与日志；最后跑完整公开 600 题。
- 保留官方模拟应用、工具集、步数上限、状态断言评分器不变，仅切换模型名称为 Base / `-pig`。
- 注意：Zapier 公布的**官方私有排行榜任务**与 GitHub 的**公开 600 题**不是同一套；公开集实验报告应明确标为 *public*。不将 DeepSeek 的 60.5% 视作无条件可复现的目标值。
- 尤其检查 PIGS 的工具暂停/恢复状态：仓库现有 continuation 为进程内状态（默认容量 64，TTL 30 分钟），因此**不要直接采用官方默认高并发**，先做 1/2/4/8 并发校准。

### 第二阶段：DeepSWE v1.1

- 先用 Pier + mini-swe-agent 跑单题、少量任务，验证代码提交补丁能被提取并在全新验证容器中评分；随后完整运行 113 题。
- Base 与 PIGS 固定同一 Agent、任务镜像、工具权限、命令超时、推理档位、上下文和调用限制。
- 保存完整轨迹、补丁、官方测试输出及每题结论。对 Base/PIGS 结论翻转、异常失败、可能存在评分器缺陷的题目实施人工审核。
- 之前依据 DeepSeek 图表推测的一轮 API 费用不是 PIGS 的实际费用预算；须先用真实令牌账单校准。

### 第三阶段：NL2Repo-Bench

- 优先跑官方 OpenHands 参考方案做 Base / PIGS 成对比较；先验证模型接口和执行路径兼容，随后完成公开 104 题。
- 如希望严格对齐 DeepSeek 的 **68.2%**，必须进一步查证/适配 DeepSeek Harness Minimal 的**实际1017版本、上下文、工具、步数和评分配置**，不能将 OpenHands 与 DeepSeek Harness 混为一谈。
- 记录完整代码仓库产物、环境构建失败、测试通过情况以及任务成功率。

## 3. 必须统一的实验规程

- **主要对照：** 同一底层模型 `MODEL`（透传）与 `MODEL-pig`（模式 B、单一业务输出）；`MODEL-pigs`（保留阶段文本）可做机制分析，**不与主结果混算**。
- **固定条件：** 模型提供商/快照或访问日期、思考档位、采样参数、外层 Agent 与提示词、工具、任务划分、沙箱镜像、最大步数、超时、并发、重试、评分器及其 Git 提交。
- **计费：** 正式统计将 PIGS `[orchestration].usage_mode` 设为 `sum`；同步保存提供商账单，区分缓存输入、非缓存输入和输出令牌。记录 PIGS 额外的内部调用和工具暂停/恢复，避免双重计数。
- **指标：** 官方端到端成功率、逐题 Base→PIGS 修复/退化数、调用次数、工具调用次数、令牌及人民币/美元费用、总耗时及超时/环境失败率。二元成对结果可报告 McNemar 检验和置信区间。
- **分阶段门槛：** 先做接口/环境冒烟检查，再做小样本费用校准，最后在冻结配置后跑**完整公开划分**。失败样本与未完成样本分开记录，不得只统计成功返回的样本。
- **外部成绩：** DeepSeek 的历史公布成绩只作背景参照；真正用于证明 PIGS 增益的是**同一条件下自己测得的 Base 和 PIGS 成对结果**。

## 4. 不列为新一轮核心测试的基准

- **τ³-bench：** 需要持续与模拟用户交互，不符合当前“尽量无多轮用户交互”的约束。
- **HLE / GPQA 等知识型测试：** 与 PIGS 长程工具执行的主要研究假设不够一致；已接入的 **IFEval** 可以保留作指令遵循不退化的辅助对照。
- **BFCL V4 Multi-Turn：** 已有官方循环适配和历史数据；建议作为**工具调用故障诊断/补充实验**而非新增主基准。其 Multi-Turn 子集不同于包含网页搜索、记忆等类别的完整 V4。
- **Terminal-Bench 4.0 / ProgramBench / Agents' Last Exam：** 可作为后续扩展；暂缓原因分别为特殊沙箱/硬件与云资源、长程重建任务成本、复杂软件环境依赖。
