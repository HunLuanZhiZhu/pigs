# Muse Spark 1.3 Contributor：强制 Full Path 的 26 道 Base 错题诊断（2026-10-08）

> **非正式评测**：本实验刻意选择历史 Base 答错的全部 26 道题，修复率绝不能视为 GSM8K 全集准确率，也不能与未配对的正式 Base 汇总分数直接作因果比较。

## 设计

- Base 来源：2026-10-05 完整、有效的 Muse Responses Base，1293/1319；原始 `reviews/muse-spark-1.3-contributor/gsm8k_main.jsonl`。
- 通过官方 EvalScope `sample_score.score.value.accuracy != 1` 识别 26 个原始错误样本；直接提取每一条 review 中的最后一个 user prompt，保留 Base 的完整 4-shot 前缀及原题，不自行重写题干。
- 模型：`muse-spark-1.3-contributor-pigfull`，由 PIGS 剥掉实验后缀后发往上游原始模型。
- API：OpenAI Responses；`temperature=0`、`reasoning.effort=low`、`stream=true`；并发 4。
- 新实验提示词：`crates/pigs-orchestrator/prompts/pre_full_{en,zh}.txt`，保留既有 Pre 的前四问，删除简单性判断与提前执行的分支，只做分析规划。提示词没有任何控制标记介绍。
- 实验后缀 `-pigfull` 在程序层强制 Pre 后进入 Executor，最终答案采用模式 B；原有 `-pig`、`-pigs` 不变。
- 隔离服务地址：`127.0.0.1:3930`，正式实验服务端口不变。
- 预测抽取与数值比较：`evalscope.metrics.math.parser.extract_answer` / `math_equal`，针对所选错误样本使用；不是一次完整 EvalScope harness 正式运行。
- 结果根目录（WSL）：`/root/pigs-eval/outputs/diagnostic/muse-full26-20261008`；`results/manifest.json`、`results/results.jsonl`、`results/progress.txt`、`results/summary.json`，`http/` 为 HTTP 原始抓包。

## 已核实结果

- 26/26 均已执行完成；0 传输错误；26/26 的 `orchestration-outcome` 路径均是 `[Pre, Executor, Post]`。
- **修复 4 道**：12、306、340、988。
- **未修复 22 道**：119、368、403、423、454、552、590、649、675、749、768、782、814、823、952、962、1001、1042、1048、1161、1176、1309。
- 每个样本只有一个 Pre、一个 Executor、一个 Post；本轮没有可观察到的 Post 驱动重规划或继续执行。因此改善不能简单归因为 Post 纠错，它可能来自 Pre 规划和 Executor 再求解。
- 26 题上 Base 原始生成记录：输入 15,277、输出 30,445、总计 45,722 tokens，平均预测延迟约 7.25 秒。
- 强制 Full：输入 103,281、输出 51,034、总计 154,315 tokens，其中 cached input 36,112、reasoning output 34,000，平均单题端到端延迟约 22.12 秒。
- 强制 Full 总 tokens 是对应 Base 的约 3.38 倍，单题平均延迟约 3.05 倍。缓存/请求条件可能随时间变化，这只是该次运行的实际用量比较。

## 解释边界

不能根据这 26 道中的 4 道修复，推断全集会从 1293/1319 变为 1297/1319；真正部署时，原本正确的 1293 题也可能被强制 Full 改错。特别是 #1001 的输出具有时间格式，严格数字抽取判为错误；不要在没有逐题核查时断言全部剩余错误都是纯算术推理错误。

下一步若要判断路线可行性，优先做 Base 正确样本的随机抽样强制 Full，测量 break rate；然后进一步分析 4 道修复与 22 道未修复的 Pre / Executor / Post 可见阶段文本。Muse 隐藏 reasoning 不可直接读取，不能声称知道加密内部思考。
