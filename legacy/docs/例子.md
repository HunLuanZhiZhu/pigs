1. 本任务需要哪些项目内部信息？（指的是项目文件信息，需要的文件路径、关键词或者其他查找方式）

## Post 阶段的三种分支

Post 阶段模型输出后，编排器根据输出末尾的控制标记决定下一步走向。共有三种分支：

### 分支一：PIGEND（任务完成）

即上方第四次请求的示例。模型判定任务完成，输出 `PIGEND`，编排器返回 `Advance::Complete`，整轮结束，PIGEND 之后的文本作为最终结果返回给用户。

### 分支二：PIGFAIL（执行错误，回到 Pre 重新规划）

模型判定当前执行离目标更远（比如执行了错误的操作、走进了死胡同），输出评审报告后追加 `PIGFAIL`。

```text7
1. 任务未完成
2. 执行错误：模型调用了 get_weather 但传错了城市参数，返回的是北京天气而非上海，与目标不符
PIGFAIL
```

编排器检测到 `PIGFAIL`，返回 Pre 阶段重新规划（受预算约束，默认最多重规划 2 次）。

第五次请求（回到 Pre 阶段）：
```json
{
  "messages": [
    {"role": "system", "content": "你是一个助手"},
    {"role": "user", "content": text8}
  ]
}
```

```text8
今天天气怎样

---

以上是本任务要求
这个任务执行中曾失败过
第 1 次失败：
{text7（Post评审报告，含PIGFAIL）}
本次回答不需要具体执行任务，而是对任务进行执行前分析，严格按要求输出这5个问题的回答
1. 本任务需要哪些项目内部信息？
2. 本任务需要哪些项目外部信息？
3. 为本任务的执行制定执行计划
4. 总结本任务的目标（goal），用于判断任务是否完成
5. 判断本任务是否为简单问题。
```

模型重新分析后输出新的 Pre 产物（text3'），进入新一轮 Executor→Post。

### 分支三：无标记（任务有进展但未完成，Post 继续回环）

模型判定任务有推进但未完全完成，输出评审报告后继续执行任务，末尾不输出任何标记。

```text7
1. 任务未完成：已获取上海天气数据，但还未格式化输出给用户
2. 执行正确：方向正确，只是缺少最后一步

让我继续完成任务，把天气信息格式化输出。
```

注意：末尾没有 `PIGEND` 也没有 `PIGFAIL`。编排器检测到无标记，返回 `Advance::Continue(Phase::Post)`，继续 Post 相位（受预算约束，默认最多 3 次无标记回环）。

**关键：Post 的输出会被累积进 `review_transcript`，text5（审阅提示词）不进 review_transcript。** 第五次请求（Post 第二次回环）采用追加式——上一轮所有内容原样保留，末尾追加 Post 输出 + 新的 text5：

```json
{
  "messages": [
    {"role": "system", "content": "你是一个助手"},
    {"role": "user", "content": text4},
    {"role": "assistant", "content": "好的我执行计划，先查天气", "tool_calls": [
      {"id": "call_abc123", "type": "function", "function": {"name": "get_weather", "arguments": "{\"city\":\"上海\"}"}}
    ]},
    {"role": "tool", "tool_call_id": "call_abc123", "content": "32°C，晴"},
    {"role": "assistant", "content": "计划执行完毕。\n上海天气晴朗"},
    {"role": "user", "content": text5},
    {"role": "assistant", "content": "1. 任务未完成：已获取上海天气数据，但还未格式化输出给用户\n2. 执行正确\n\n让我继续完成任务，把天气信息格式化输出。\n上海今天 32°C，晴天，适合户外活动。"},
    {"role": "user", "content": text5}
  ]
}
```

相比第四次请求，第五次请求的 messages 数组：
- 前缀完全不变：system + user(text4) + Executor 轨迹 + user(text5)
- **追加 Post 第一次的 assistant 输出**（评审报告 + 继续执行）
- **追加新的 user(text5)**（再次审阅）

这种追加式对上游 API 的前缀缓存友好——只有新增部分需要重新计算。

模型再次验收：

```text8
1. 任务完成：天气信息已格式化输出
2. 执行正确
PIGEND
```

整轮结束。

## 注意事项

1. **Post 相位保留原始 user（text4）**：Post 的输入始终包含 Executor 指令（text4），让模型知道任务目标是什么。这是 [for_post](file:///d:/AIWorkSpace/pigs/crates/pigs-api/src/protocol.rs) 的行为：保留原 user，追加轨迹和审阅提示词。

2. **Post 回环采用追加式**：每次 Post 回环（无标记分支），Post 自己的 assistant 输出会被累积进 `review_transcript`。下次 Post 请求通过 `for_post` 在现有 messages 数组末尾追加（不重建），text5 不进 review_transcript 所以每轮重新追加。这种追加式对上游 API 的前缀缓存友好。

3. **预算约束**：无标记回环默认最多 3 次（`max_post_iterations`），PIGFAIL 重规划默认最多 2 次（`max_pre_replans`）。超出预算报错，**绝不**算成功完成。

4. **三种协议行为一致**：OpenAI Chat / Anthropic Messages / OpenAI Responses 三种协议在 Post 阶段都保留原始 user 输入，只是消息格式不同。

5. **PIGFAIL 衔接提示词**：失败路径的衔接文字（"这个任务执行中曾失败过 / 第 N 次失败"）定义在 `pigs-prompts/prompts/failure_paths_{zh|en}.txt` 模板文件中，支持中英双语。
